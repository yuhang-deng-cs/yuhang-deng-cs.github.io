TicketFlow — event ticketing under load

2026

Java 21 / Spring Boot 3 API, React 19 front end, deployed to AWS with Terraform.

Problem
When many buyers hit the same ticket tier at once, a naive read-then-write booking flow oversells seats and double-charges on retries.
Approach
Atomic conditional updates (… WHERE available_capacity >= :qty) plus optimistic locking; Idempotency-Key on booking and checkout; 10-minute holds released by a scheduled sweeper; JWT auth with role-based access; trace IDs in every log line.
Verified
A concurrency test runs 50 threads against 10 tickets: exactly 10 orders, 40 clean 409s, 0 oversold. k6 stress script, Prometheus/Grafana dashboards, and CI that runs tests, builds Docker images and validates Terraform.

Multi-tenant RAG support assistant

2025 – present

FastAPI service with a React chat workspace that answers staff questions from internal documents.

Problem
Company knowledge bases mix public guidelines with confidential department docs, and dumping whole documents into an LLM prompt is slow, expensive and leaks data across teams.
Approach
Per-tenant isolation in PostgreSQL + pgvector; uploads return 202 immediately and a Celery/Redis worker chunks and embeds in the background; an intent router skips retrieval for small talk; retrieved chunks are pruned before prompting; answers stream over SSE with source citations. JWT + RBAC throughout.
Result
Context pruning removes 70–85% of prompt tokens on typical queries. Whole stack starts with Docker Compose; covered by a pytest suite.

Evaluating LLM methods for trip planning

Mar – Jun 2026

Master's capstone, University of Queensland.

Question
LLMs write fluent itineraries but invent places and break budget, opening-hour and distance limits. Which techniques actually fix that?
Approach
Built an evaluation harness: a POI knowledge base for South-East Queensland, 40 controlled scenarios, and a rule-based validator. Compared four methods (direct prompting, structured JSON, RAG, and RAG + validator-guided repair) across 160 runs with automated metrics and charts.
Finding
Retrieval grounding lifted factual accuracy from 37% to 100%; adding the validator repair loop raised constraint satisfaction from 93.4% to 99.8%.
